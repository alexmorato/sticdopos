📖 Formato esperado del JSON

Estructura general

El JSON debe ser un array de objetos con la siguiente estructura:

{ "question": "Texto de la pregunta", "options_good": ["Respuesta correcta"], "options_bad": [ "Respuesta incorrecta 1", "Respuesta incorrecta 2", "Respuesta incorrecta 3" ], "explanation": "Texto de la explicación (opcional)" }

Campos requeridos

  • question: Texto de la pregunta
  • options_good: Array de respuestas correctas (generalmente una)
  • options_bad: Array de respuestas incorrectas
  • explanation: (Opcional) Explicación o pista. Si hay una sola respuesta correcta, se usa como rationale; si hay varias correctas, se conserva como campo independiente

Ejemplo completo

[ { "question": "¿Qué modelo usa píxeles o celdas?", "options_good": ["Ráster"], "options_bad": ["Vectorial", "Topológico", "Matricial"], "explanation": "Malla de celdas con valores (ej: orfotos)" } ]

📋 Reglas de Generación de Preguntas

Criterios principales

  • Dificultad: 40% fáciles, 40% medias, 20% difíciles
  • Calidad: Conceptos importantes y frecuentemente evaluables
  • Respuestas: Una correcta, tres incorrectas plausibles y similares
  • Lenguaje: Claro, preciso, sin ambigüedades
  • Sin duplicados: Evitar preguntas repetidas
  • Enfoque especial: 50% sobre aspectos que suelen generar errores

Aspectos que suelen generar errores

  • Excepciones y límites
  • Requisitos y incompatibilidades
  • Plazos y mayorías necesarias
  • Órganos competentes
  • Diferencias entre instituciones similares

Explicaciones

Cada pregunta debe incluir una explicación que:

  • Justifique por qué la respuesta correcta es válida
  • Explique por qué las opciones incorrectas son erróneas
  • Mencione artículos o normas relevantes cuando proceda
  • Destaque confusiones habituales
  • Ayude a comprender el concepto, no solo a memorizarlo
